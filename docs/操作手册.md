## 1. 系统概述

StockScan 是一套基于 A 股历史数据的**多规则选股系统**，从 StockDB 数据库（5490 只 A 股，2020 年至今）读取行情数据，支持用户自定义多条筛选规则，在任意交易日快速找出符合条件的股票。

### 核心特性

| 特性 | 说明 |
|------|------|
| 多规则组合 | 支持 7 大类 60 余条规则自由组合 |
| 全部/部分匹配 | 可设置"全部满足"或"至少满足 N 条" |
| 向量化计算 | 对 5480 只股票批量 numpy 计算，8–10 秒出结果 |
| 拖拽排序 | 方案编辑器支持规则拖拽排序、一键启禁 |
| 历史回溯 | 可对任意历史交易日运行选股，结果永久保存 |
| CSV 导出 | 结果一键导出为 Excel 可读的 CSV 文件 |
| 只读数据源 | 对 StockDB 仅有 SELECT 权限，不影响数据采集 |

### 技术栈

| 层次 | 技术 |
|------|------|
| 后端 | Python 3.13 + FastAPI + Uvicorn |
| 前端 | Vue 3 + Vite + Element Plus + vuedraggable |
| 数据库 | PostgreSQL 16（同实例，独立 `stockscan` 库） |
| ORM | SQLAlchemy 2.0 + Alembic 迁移 |
| 数据计算 | pandas 3.0 + pandas-ta + numpy |

### 5.1 选股运行页

这是系统的核心操作页面。

**操作步骤：**

1. **选择选股方案** — 下拉框中选择已有方案（内置方案带 `[内置]` 标识）
2. **选择交易日期** — 日期选择器，默认自动填入最新交易日
3. **点击「开始选股」** — 按钮变为"正在筛选..."，等待结果（通常 8–15 秒）
4. **查看结果** — 统计卡片显示扫描总数、完全匹配数、部分匹配数、耗时
5. **导出 CSV** — 结果出现后，点击「导出 CSV」下载，可用 Excel 打开

**结果表格字段说明：**

| 字段 | 说明 |
|------|------|
| 代码 | 股票代码（如 `000049.SZ`） |
| 名称 | 股票简称 |
| 匹配 | `全匹配`（所有规则满足）或 `N/M`（满足 N 条，共 M 条） |
| 收盘价 | 当日收盘价（元） |
| 涨幅% | 当日涨跌幅（红色为涨，绿色为跌） |
| 换手率% | 当日换手率 |
| 流通市值(亿) | 流通市值，已换算为亿元 |
| 成交量(手) | 当日成交量 |

表格支持按任意列排序，默认按匹配规则数从多到少排列。

**注意事项：**
- 只能选择有行情数据的交易日，非交易日会提示错误
- 同一方案+日期重复运行会生成新记录（历史记录页可查所有运行结果）
- 运行时间较长（8–15 秒）属正常，系统正在对 5000+ 只股票批量计算

### 5.3 方案编辑器

点击方案列表的「编辑」按钮进入。

#### 方案基本设置

| 字段 | 说明 |
|------|------|
| 方案名称 | 自定义名称，建议简洁 |
| 匹配模式 | **全部匹配**（所有启用规则均须满足）或**部分匹配**（满足 N 条即可） |
| 最少匹配数 | 部分匹配模式下填写，如设 5 则满足任意 5 条规则即筛出 |
| 描述 | 可选，记录策略逻辑 |

修改后点击「保存方案」生效。

#### 规则列表操作

- **拖拽排序**：拖动左侧的 `≡` 图标调整规则顺序（顺序影响展示，不影响计算）
- **启用/禁用**：右侧开关控制，禁用的规则不参与计算，行变灰
- **编辑规则**：点击「编辑」修改规则的操作符和参数值
- **删除规则**：点击「删除」从方案中移除该规则

#### 从模板添加规则

1. 点击右上角「添加规则」，右侧展开模板库面板
2. 按分类折叠展示所有 60 条模板
3. 点击任意模板，自动以默认参数添加到规则列表
4. 可在添加后点击「编辑」调整参数值

#### 编辑规则弹窗

| 字段 | 说明 |
|------|------|
| 规则名称 | 自定义显示名称 |
| 操作符 | `>` `≥` `<` `≤` `=` 或 `区间[min,max]` |
| 参数值 (JSON) | 规则阈值，JSON 格式，见[规则参数说明](#8-规则参数说明) |
| 回溯天数 | 引擎取多少天历史数据，0 表示仅当日 |

## 6. 内置选股方案

### 方案一：下午盯盘选股法

**设计理念**：适合午后盯盘，筛选当日有明显量价配合、趋势健康的强势股。

**匹配模式**：部分匹配，满足 7 条中任意 5 条即筛出。

| # | 规则名称 | 指标 | 条件 | 数据源 |
|---|----------|------|------|--------|
| 1 | 涨幅3%-5% | pct_chg | 3% ≤ 值 ≤ 5% | daily_price |
| 2 | 量比>1 | volume_ratio | 值 > 1 | daily_fundamental |
| 3 | 换手率2%-10% | turnover_rate | 2% ≤ 值 ≤ 10% | daily_fundamental |
| 4 | 流通市值50亿-1500亿 | circ_mv | 500000 ≤ 值 ≤ 15000000（万元） | daily_fundamental |
| 5 | 成交量台阶式放大 | vol_step_up | 近8日至少3日连续递增或分段均量逐段递增 | daily_price |
| 6 | 均线多头发散 | ma_alignment_diverge | MA5>MA10>MA20>MA60 且各线斜率向上 | daily_price |
| 7 | 股价在日均价上方 | close_vs_vwap | 收盘价 > 当日VWAP近似值 | daily_price |

**使用建议**：
- 规则 5 和 6 要求回溯历史数据，数据量不足时（历史不足 60 交易日）会返回 False
- 规则 7 的 VWAP 用 `amount×1000 / (vol×100)` 近似，反映收盘价是否强于当日均价

---

### 方案二：成长潜力选股

**设计理念**：综合趋势、量能、估值、资金流的全面筛选。

**匹配模式**：部分匹配，满足 9 条中任意 6 条即筛出。

| # | 规则名称 | 条件 |
|---|----------|------|
| 1 | 价格在MA20上方 | 收盘 > MA20 |
| 2 | 均线多头排列 | MA5>MA10>MA20>MA60 |
| 3 | 换手率2%-10% | 2% ≤ 换手率 ≤ 10% |
| 4 | 成交量>MA20均量*1.2 | 今日量 > 20日均量 × 1.2 |
| 5 | PE_TTM 0-50 | 0 ≤ PE_TTM ≤ 50 |
| 6 | PB 0-8 | 0 ≤ PB ≤ 8 |
| 7 | 主力净流入>0 | 当日主力净流入 > 0 |
| 8 | 大单净流入>0 | 当日大单净流入 > 0 |
| 9 | 流通市值20亿-500亿 | 200000 ≤ circ_mv ≤ 5000000（万元） |

## 8. 规则参数说明

编辑规则时，「参数值」字段为 JSON 格式。不同操作符对应不同格式：

### 操作符格式

| 操作符 | JSON 格式 | 示例 |
|--------|-----------|------|
| `>` (gt) | `{"v": 数值}` | `{"v": 1}` — 量比大于1 |
| `>=` (gte) | `{"v": 数值}` | `{"v": 365}` — 上市超过365天 |
| `<` (lt) | `{"v": 数值}` | `{"v": 30}` — RSI低于30 |
| `<=` (lte) | `{"v": 数值}` | `{"v": 50}` |
| `=` (eq) | `{"v": 数值}` | `{"v": 1}` — 布尔型（1=真） |
| `区间` (between) | `{"min": 下限, "max": 上限}` | `{"min": 3, "max": 5}` — 涨幅3%-5% |

### 带附加参数的规则

部分规则的参数值中除阈值外还含结构参数：

| 规则指标 | 参数示例 | 参数说明 |
|----------|----------|----------|
| `close_vs_ma` | `{"period": 20, "v": 0}` | `period`：均线周期（5/10/20/60） |

## 11. 选股引擎原理

引擎分四个阶段顺序执行，每个阶段各负责不同类型的规则：

```
阶段 1：FundamentalEvaluator（基本面）
  → SQL 单次查询 daily_fundamental / stock_basic
  → 覆盖：PE/PB/PS/股息率/换手率/量比/市值/ST过滤/板块/上市年限

阶段 2：PriceEvaluator（价格/均线）[向量化]
  → 读取过去 90 天 OHLCV 数据
  → Pivot 为 (日期 × 股票) 矩阵，numpy 批量计算
  → 覆盖：pct_chg/VWAP/MA/均线排列/金叉/新高/涨停板/vol_step_up 等

阶段 3：FlowEvaluator（资金流）
  → 读取 money_flow 表
  → 覆盖：主力/大单/超大单净流入、连续/累计净流入

阶段 4：TechnicalEvaluator（技术指标）
  → 读取 OHLCV 数据，使用 pandas_ta 计算
  → 覆盖：MACD/KDJ/RSI/CCI/威廉%R/ATR/OBV/BOLL

汇总：
  → 合并四阶段结果 {ts_code: {rule_id: bool}}
  → 按全匹配/部分匹配分类
  → 写入 screening_result + screening_result_detail
```

### 关键实现细节

**vol_step_up（台阶式放大）**：
检查近 N 日（默认8日）成交量，满足以下任一条件即为真：
- 存在连续 `min_consecutive`（默认3）天量的**元素个数**递增（即2次连续上涨转折即满足"3天"）
- 三段（各约 N/3 天）均量呈递增趋势（s3 > s2 > s1）

**ma_alignment_diverge（均线多头发散）**：
同时满足：① MA5>MA10>MA20>MA60；② 各均线今日值 > 3交易日前值（斜率向上）

**VWAP 近似**：
`VWAP ≈ amount × 1000 / (vol × 100)`，其中 amount 单位为千元，vol 单位为手（100股）。

## 13. 常见问题排查

### 问题：启动后端报 `ModuleNotFoundError: No module named 'backend'`

**原因**：必须从项目根目录运行。

```bash
# 正确
cd /Users/zyzbot/MyProject/StockScan
python3 -m uvicorn backend.main:app --port 8000

# 错误（不要在 backend/ 目录下运行）
cd backend && python3 -m uvicorn main:app --port 8000
```

---

### 问题：选股返回 `400 - XXX is not a trading day`

**原因**：所选日期在 trade_calendar 中 `is_open=0`（节假日/周末），或该日期无行情数据。

**解决**：页面默认自动填入最新交易日，改回即可；或在日期选择器中选择工作日。

---

### 问题：选股结果为 0 条

可能原因：
1. 规则条件过严，无股票满足。尝试放宽参数（如扩大涨幅区间）
2. 回溯天数不足，均线/技术指标需要历史数据（如 MA60 需要 60 交易日，约90自然日）
3. 选了太早的历史日期（2020 年前），数据可能不完整

---

### 问题：选股耗时超过 30 秒

可能原因：
1. 方案中含多条技术指标规则（MACD/KDJ/RSI），pandas_ta 计算慢
2. 数据库连接压力大（StockDB 正在更新数据）

**解决**：先用基本面+价格规则过滤，再加技术指标；或错开 StockDB 数据更新时间。

---

### 问题：前端页面空白或接口报错

1. 确认后端已启动：`curl http://localhost:8000/api/health`
2. 检查 vite.config.ts 代理配置（默认 `/api` 代理到 `localhost:8000`）
3. 查看浏览器控制台 Network 标签的请求详情

---

### 问题：数据库初始化脚本失败

若报 `encoding incompatible`，确保脚本使用 `TEMPLATE template0`（已修复）。

若报 `permission denied`，确保以 `zyzbot`（PostgreSQL 超级用户）身份运行 `init_db.sh`。

---
